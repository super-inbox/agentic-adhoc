## Why Curify's benchmark total is exactly 0.000

Not a scoring artifact. One hard gate zeroes every case:

| hard gate | curify | codex |
|---|---|---|
| completed | 16/21 | 20/21 |
| artifact_contract | **11/21** | 13/21 |
| **all_inputs_consumed** | **0/21** | **21/21** |
| production_gate | 14/21 | 15/21 |
| judge_coverage | 21/21 | 19/21 |
| judge_no_fatal_issues | 12/21 | 17/21 |

**All 21 tasks supply a reference image. Curify loaded it on 0 of them**
(`loaded_asset_count` 0, `required_asset_count` 1); Codex loaded it on 21/21.
`target_reference_utilization` is 0.0 across the board.

This is the same defect two earlier measurements pointed at independently — the
21q asset count (21/30) and the 08-14 canary that invented a jacket. It is now
measured rather than inferred, and it is the highest-leverage fix available:
the reference gate alone caps the benchmark total at 0 no matter how much the
generation improves.

is scoring a generic image against a specific brief.
